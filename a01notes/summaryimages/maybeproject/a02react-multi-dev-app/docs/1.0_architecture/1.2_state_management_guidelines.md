# 1.0 State Management & Inter-Component Communication Guidelines

## 2.0 State Scope Hierarchy
2.1 Component Local State (`useState`): Used for UI toggles, input field tracking, and modal visibility inside a single component.
2.2 Feature-Scoped State (Custom Hooks): Managed within `src/features/feature<N>/hooks/` to isolate feature business logic from UI rendering.
2.3 Global Shared Application State (`AppContext`): Used strictly for application-wide states such as user authentication tokens, active theme, and global notifications.

## 3.0 Inter-Component Communication Patterns
3.1 Parent-to-Child Communication:
    - 3.1.1 Parent component holds state data objects.
    - 3.1.2 Data objects are passed down to child components as explicit read-only `props`.
    - 3.1.3 Child components consume props directly without direct mutation.
3.2 Child-to-Parent Communication:
    - 3.2.1 Parent component defines action handler functions (callbacks).
    - 3.2.2 Parent passes action handler functions down to child via props (e.g., `onSendMessage={handleMessage}`).
    - 3.2.3 Child invokes the callback function, passing structured object payloads back up to the parent.
3.3 Sibling-to-Sibling Communication:
    - 3.3.1 Lift state up to closest common parent container (e.g., `App.jsx`).
    - 3.3.2 Pass state down to Sibling A via props, and pass callback function to Sibling B via props.

## 4.0 Immutability & Object Update Rules
4.1 Rule 1: Always update object state using spread operator copy syntax (e.g., `setUserData(prev => ({ ...prev, name: 'New' }))`).
4.2 Rule 2: Never directly mutate state objects (e.g., Avoid `userData.name = 'New'`).
