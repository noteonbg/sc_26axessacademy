# 1.0 Team Git Branching & Integration Strategy

## 2.0 Core Repository Branch Hierarchy
2.1 `main` Branch: Protected production release branch. Direct commits are strictly prohibited.
2.2 `develop` Branch: Shared integration branch where all 6 feature branches are merged during sprint cycles.
2.3 `feature/*` Branches: Short-lived feature branches created per user story by individual developers.

## 3.0 Developer Branch Naming Conventions
3.1 Developer 1 (Feature 1 Auth): `feature/dev1-auth-security`
3.2 Developer 2 (Feature 2 Catalog): `feature/dev2-product-catalog`
3.3 Developer 3 (Feature 3 Cart): `feature/dev3-shopping-cart`
3.4 Developer 4 (Feature 4 Checkout): `feature/dev4-payment-checkout`
3.5 Developer 5 (Feature 5 User Profile): `feature/dev5-user-profile`
3.6 Developer 6 (Feature 6 Analytics & Lead Integrator): `feature/dev6-admin-analytics`

## 4.0 Standard Operating Instructions for Developers 1 through 5
4.1 Step 1 (Checkout Latest Code):
    - `git checkout develop`
    - `git pull origin develop`
    - `git checkout -b feature/dev<N>-<feature-name>`
4.2 Step 2 (Scoped Development):
    - Make commits strictly within your designated folder `src/features/feature<N>_/`.
    - Avoid editing other feature directories or shared root files without Tech Lead approval.
4.3 Step 3 (Push & PR Creation):
    - `git push origin feature/dev<N>-<feature-name>`
    - Create a Pull Request targeting the `develop` branch.
4.4 Step 4 (Assign Reviewer):
    - Assign Developer 6 as the mandatory PR reviewer.
    - Do NOT self-merge PRs.

## 5.0 Standard Operating Instructions for Developer 6 (Lead Integrator & Merging Lead)
5.1 Step 1 (Feature 6 Delivery):
    - Develop Feature 6 inside `src/features/feature6_analytics/` on branch `feature/dev6-admin-analytics`.
5.2 Step 2 (PR Code Audit & Verification):
    - Review PRs submitted by Developers 1 through 5.
    - Verify zero file collisions outside designated feature folders.
    - Confirm all public exports pass through `src/features/feature<N>/index.js`.
5.3 Step 3 (Merge Execution to `develop`):
    - Merge approved PRs into `develop` branch.
5.4 Step 4 (Local Integration Testing):
    - `git checkout develop` && `git pull origin develop`
    - Run `npm test` and `npm run build` to verify zero build errors.
