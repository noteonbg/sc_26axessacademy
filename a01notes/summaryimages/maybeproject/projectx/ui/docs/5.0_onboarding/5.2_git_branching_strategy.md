# 1.0 ProjectX Full-Stack Monorepo Git Strategy & Onboarding Guidelines

## 2.0 Monorepo Branch Hierarchy & Two-Phase Development Plan
2.1 `main` Branch: Protected production branch containing deployed release tags (`release/phase-1-ui`, `release/phase-2-fullstack`).
2.2 `develop-ui` Branch: Integration branch for Phase 1 React UI development (`projectx/ui/`).
2.3 `develop-backend` Branch: Integration branch for Phase 2 Spring Boot Backend development (`projectx/backend/`).
2.4 `feature/*` Branches: Short-lived workspace branches created per feature story by individual developers.

## 3.0 Phase 1 (UI Layer) Branch Naming Conventions
3.1 Developer 1 (Feature 1 Auth): `feature/ui-dev1-auth`
3.2 Developer 2 (Feature 2 Catalog): `feature/ui-dev2-catalog`
3.3 Developer 3 (Feature 3 Cart): `feature/ui-dev3-cart`
3.4 Developer 4 (Feature 4 Checkout): `feature/ui-dev4-checkout`
3.5 Developer 5 (Feature 5 User Profile): `feature/ui-dev5-profile`
3.6 Developer 6 (Feature 6 Analytics & Lead Integrator): `feature/ui-dev6-analytics`

## 4.0 Phase 2 (Spring Boot Backend Layer) Branch Naming Conventions
4.1 Developer 1 (Feature 1 Auth API): `feature/backend-dev1-auth`
4.2 Developer 2 (Feature 2 Catalog API): `feature/backend-dev2-catalog`
4.3 Developer 3 (Feature 3 Cart API): `feature/backend-dev3-cart`
4.4 Developer 4 (Feature 4 Checkout API): `feature/backend-dev4-checkout`
4.5 Developer 5 (Feature 5 User Profile API): `feature/backend-dev5-profile`
4.6 Developer 6 (Feature 6 Analytics API & Lead Integrator): `feature/backend-dev6-analytics`

## 5.0 Standard Operating Instructions for Developers 1 through 5
5.1 Step 1 (Branch Initialization):
    - For Phase 1: `git checkout develop-ui` && `git pull origin develop-ui` && `git checkout -b feature/ui-dev<N>-<name>`
    - For Phase 2: `git checkout develop-backend` && `git pull origin develop-backend` && `git checkout -b feature/backend-dev<N>-<name>`
5.2 Step 2 (Folder Isolation Enforcement):
    - Phase 1 UI commits MUST remain strictly inside `projectx/ui/src/features/feature<N>_/`.
    - Phase 2 Backend commits MUST remain strictly inside `projectx/backend/` matching Feature `<N>`.
5.3 Step 3 (Pull Request Creation):
    - Push branch and create PR targeting `develop-ui` (Phase 1) or `develop-backend` (Phase 2).
5.4 Step 4 (Assign Reviewer):
    - Assign Developer 6 as the mandatory reviewer. Self-merging is strictly prohibited.

## 6.0 Standard Operating Instructions for Developer 6 (Lead Integrator & Merging Lead)
6.1 Step 1 (Feature Delivery):
    - Deliver Feature 6 on branch `feature/ui-dev6-analytics` (Phase 1) and `feature/backend-dev6-analytics` (Phase 2).
6.2 Step 2 (PR Code Audit & Verification):
    - Audit PRs submitted by Developers 1 through 5 for directory isolation and public API export compliance (`index.js`).
    - Verify Phase 2 Spring Boot REST payloads match specifications defined in `projectx/docs/3.0_api_contracts/`.
6.3 Step 3 (Integration Branch Merges):
    - Merge approved UI PRs into `develop-ui`.
    - Merge approved Backend PRs into `develop-backend`.
6.4 Step 4 (Release Tagging & Production Merges to `main`):
    - Phase 1 Release: Merge `develop-ui` into `main` with release tag `release/phase-1-ui`.
    - Phase 2 Release: Merge `develop-backend` into `main` with release tag `release/phase-2-fullstack`.
