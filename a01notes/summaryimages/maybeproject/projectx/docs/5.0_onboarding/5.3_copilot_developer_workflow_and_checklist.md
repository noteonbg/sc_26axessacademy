# 1.0 Developer Workflow & Checklist for Implementing React Components using GitHub Copilot

## 2.0 Step-by-Step Implementation Workflow
- **2.1** Step 1 (Domain & Contract Alignment):
  - Read your assigned User Story in `projectx/docs/2.0_requirements_and_stories/`.
  - Review your feature API data object schema in `projectx/docs/3.0_api_contracts/`.
- **2.2** Step 2 (Context Setup for GitHub Copilot):
  - Open relevant target files in VS Code editor tabs (`src/App.js`, `src/features/feature<N>/index.js`).
  - Write explicit JSDoc comments describing props object structure and callback handler signatures before generating code with Copilot.
- **2.3** Step 3 (Component Construction in Feature Folder):
  - Place private feature components inside `src/features/feature<N>/components/`.
  - Place feature-specific custom hooks inside `src/features/feature<N>/hooks/`.
  - Place feature HTTP mock services inside `src/features/feature<N>/services/`.
- **2.4** Step 4 (Public API Exporting):
  - Export public components in `src/features/feature<N>/index.js`.
  - Verify zero deep relative imports into another developer's private feature components.
- **2.5** Step 5 (Inter-Component Communication):
  - Pass data objects down from Parent to Child via typed props.
  - Emit event payload objects up from Child to Parent via callback props.

## 3.0 Newcomer Developer Verification Checklist
- **3.1** Category 1: Folder Isolation Verification
  - [ ] Are all my new files strictly inside my assigned folder `src/features/feature<N>/`?
  - [ ] Did I refrain from editing other developers' feature directories?
- **3.2** Category 2: Public API & Encapsulation Verification
  - [ ] Is my public component exported through `src/features/feature<N>/index.js`?
  - [ ] Did I avoid deep internal imports into other feature folders?
- **3.3** Category 3: Inter-Component Communication Verification
  - [ ] Does my child component accept data objects via props without mutating them directly?
  - [ ] Does my child component trigger callback functions emitting structured message/payload objects back to the parent?
- **3.4** Category 4: GitHub Copilot Audit Verification
  - [ ] Did I review Copilot-generated code to ensure no unused dependencies or fake prop names were introduced?
  - [ ] Did I verify state updates use immutable copy syntax (`setObj(prev => ({ ...prev, key: val }))`)?
- **3.5** Category 5: Runtime & Build Verification
  - [ ] Does `npm start` compile cleanly with zero ESLint errors?
  - [ ] Does the UI render correctly when navigating to my feature?
