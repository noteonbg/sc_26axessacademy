# 1.0 Folder Structure Standards & Multi-Developer Isolation Rules

## 2.0 Architectural Philosophy
2.1 Domain-Driven Design (DDD): Software modules are partitioned by business domain capabilities rather than technical layer types.
2.2 Developer Autonomy: Each of the 6 developers possesses full technical autonomy over their allocated feature slice directory (`src/features/feature<N>`).
2.3 Elimination of Merge Blockers: Zero overlap in file modifications between Developer 1 and Developer 6 during daily sprint execution.

## 3.0 Directory Organization Specifications
3.1 Root Directory (`/`): Contains build infrastructure, package manifests, and project-wide documentation.
3.2 Documentation Directory (`/docs/`): Stores categorized technical specs, user story requirements, API contracts, design tokens, and onboarding manuals.
3.3 Source Code Directory (`/src/`): Contains the React application codebase, split into common shared assets and 6 feature slices.

## 4.0 Feature Slice Module Composition Rules
4.1 Folder naming convention: `src/features/feature<number>_<name>/` using lowercase snake_case.
4.2 Mandatory `index.js` file: Every feature folder MUST contain an `index.js` file serving as the public API export gatekeeper.
4.3 Encapsulated Sub-directories:
    - 4.3.1 `components/`: UI components rendered exclusively inside this feature.
    - 4.3.2 `hooks/`: Stateful React hooks managing logic exclusive to this feature.
    - 4.3.3 `services/`: API interaction logic and network calls exclusive to this feature.
    - 4.3.4 `styles/`: CSS modules scoped exclusively to components within this feature.

## 5.0 Strict Anti-Pattern Guidelines
5.1 Anti-Pattern 1: Never perform deep relative imports into another developer's private components (e.g., `import X from '../feature2/components/PrivateComponent'`).
5.2 Anti-Pattern 2: Never place feature-specific UI components into the shared `src/components/` directory.
5.3 Anti-Pattern 3: Never pollute global App state with local feature form inputs.
