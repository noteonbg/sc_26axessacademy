# 1.0 Component Planning & Route Data Passing Conceptual Guide

## 2.0 Architectural Rule: Planning vs. Trial-and-Error
- **2.1** Anti-Pattern Warning: Never use "code and find out" trial-and-error in a team codebase. It produces broken prop signatures, mismatched route parameter names, duplicate state, and blocked merges.
- **2.2** Standard Practice: Plan what information each component receives from props or routes before writing code.

## 3.0 Step 1: Define Component Role & Hierarchy
- **3.1** Parent Component (Feature Module): Holds overall screen state and manages workflow.
- **3.2** Child Component: Renders specific UI cards or forms and sends user actions back to parent.
- **3.3** Route Page Component: Renders an entire screen when the user visits a specific web link (URL).

## 4.0 Step 2: Understanding Route Information Passing (Simple Concept)
- **4.1** What is Route Data Passing?: When a user moves from Screen A to Screen B, the Route acts like a delivery messenger carrying information from Screen A to Screen B.
- **4.2** 3 Ways Information Moves Through Routes:
  - Type 1 (Resource ID in Web Link): Information attached directly inside the web link (e.g. `/products/101` carries Product ID `101`).
  - Type 2 (Filter Options in Web Link): Information attached at the end of the web link (e.g. `/catalog?category=hardware` carries Category Filter `hardware`).
  - Type 3 (Silent Data Package Handover): A hidden data package handed from Screen A to Screen B during navigation without showing in the web link bar.

## 5.0 Step 3: Simple Real-World Example (3-Screen Flow)
- **5.1** Screen 1 (Catalog Screen):
  - User Action: User selects "Hardware Category".
  - Information Passed via Route: `category = hardware` is attached to the route link.
  - Target Component Action: Catalog component receives `category = hardware` from the route and displays hardware items.
- **5.2** Screen 2 (Product Details Screen):
  - User Action: User clicks on "Cloud Server Node #101".
  - Information Passed via Route: Product ID `101` is attached to the route link (`/products/101`).
  - Target Component Action: Product Details component receives Product ID `101` from the route and loads details for server #101.
- **5.3** Screen 3 (Checkout Screen):
  - User Action: User clicks "Buy Product #101 Now".
  - Information Passed via Route: A complete Order Package `{ Item: "Cloud Server Node", Price: $299 }` is handed to the route.
  - Target Component Action: Checkout component receives this Order Package from the route and displays the payment total.

## 6.0 Step 4: Cross-Developer Integration Protocol
- **6.1** Feature Barrier Rule: Cross-feature component consumption MUST pass exclusively through `src/features/feature<N>/index.js`.
- **6.2** Shared Screen Integration: Developer A and Developer B components integrate cleanly inside `src/App.js` routes or shared page layouts.

## 7.0 Pre-Coding Component Blueprint Template
- **7.1** Blueprint Structure:
```javascript
/**
 * COMPONENT BLUEPRINT: [ComponentName]
 * Developer Owner: Developer [N]
 * --------------------------------------------------
 * 1. Role: [What does this component do?]
 * 2. Inputs (Information Received):
 *    - Received via Props: { userObject }
 *    - Received via Route: Product ID 101 or Category "hardware"
 * 3. Outputs (Information Sent):
 *    - Sent via Callbacks: onSelect(item)
 *    - Sent via Route: Order Package sent to Checkout Screen
 * 4. Integration Site: Consumed inside App.js Route [/screen-path]
 */
```

## 8.0 Beginner Component & Route Planning Checklist
- **8.1** Folder Check: Are all my new files inside my assigned folder `src/features/feature<N>/`?
- **8.2** Route Information Check: Did I identify what information my screen needs to receive from the route link?
- **8.3** Public Export Check: Is my main screen component exported in `src/features/feature<N>/index.js`?
- **8.4** Fallback Check: Does my screen display a helpful message if a user opens the route link without selecting an item?

## 9.0 Summary Matrix for Beginners
- **9.1** Web Link ID (`/item/101`): Use when anyone opening the web link must see item #101.
- **9.2** Web Link Filter (`?type=search`): Use when passing search keywords or category filters.
- **9.3** Silent Route Handover: Use when passing a full checkout package from screen to screen.
