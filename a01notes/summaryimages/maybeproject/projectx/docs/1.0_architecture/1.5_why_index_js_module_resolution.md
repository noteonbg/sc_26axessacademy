# 1.0 Why the Gatekeeper File Must Be Named `index.js`

## 2.0 Module Resolution Mechanics in JavaScript & React Bundlers
- **2.1** Default Directory Entrypoint: JavaScript bundlers (Webpack, Vite, Rollup) and Node.js automatically treat `index.js` as the default entrypoint file when importing a directory folder path.
- **2.2** Path Resolution Equivalent:
  - Statement `import { Component } from '../feature1_user'`
  - Is automatically resolved by JavaScript as `import { Component } from '../feature1_user/index.js'`.

## 3.0 Architectural Benefits of the `index.js` Naming Convention
- **3.1** Clean Package-Like Syntax: Allows feature folders (`feature1_user/`) to behave like self-contained internal npm packages.
- **3.2** Hiding Internal File Details: External developers (like Suresh) do not need to know internal file names inside Ramesh's `components/` subfolder.
- **3.3** Elimination of Redundant Path Typing: Prevents typing long paths like `import { X } from '../feature1_user/publicExports.js'`.

## 4.0 What Happens If You Use a Different Name (e.g. `public.js` or `barrier.js`)
- **4.1** Lost Automatic Resolution: If named `public.js`, bundlers cannot automatically resolve `import { X } from '../feature1_user'`.
- **4.2** Forced File Name Exposure: Other developers would be forced to explicitly append the filename: `import { X } from '../feature1_user/public.js'`.
